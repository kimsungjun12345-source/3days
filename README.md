# 셋돌하나 — 3일씩 다시 쌓는 습관 앱

매일 이어가야 한다는 압박 대신 **3일 단위의 약속과 복귀 경험**에 초점을 둔 습관 앱입니다. 하루를 놓쳐도 이미 해낸 날과 쌓은 돌은 사라지지 않습니다.

[Google Play에서 보기](https://play.google.com/store/apps/details?id=com.trevicode.setdolhana) · [제품 방향과 지표](docs/POSITIONING.md) · [앱 빌드 안내](BUILD.md)

## 제품에서 해결한 문제

연속 기록이 끊기면 이전의 노력이 모두 사라진 것처럼 느껴지는 경험을 바꾸고자 했습니다. 사용자는 행동 하나를 3일 동안 시도하고, 3일을 채우면 돌을 쌓습니다. 잠시 쉬었다가 돌아와도 누적 기록은 유지하며, 다시 시작한 횟수도 보여줍니다.

| 제품 결정 | 구현된 방식 |
| --- | --- |
| 시작 부담 줄이기 | 긴 목표 대신 3일짜리 사이클 |
| 중단 후 복귀 돕기 | 누적 기록 유지, 다시 쌓기 흐름 |
| 기록을 눈에 보이게 | 돌탑·정원, 달력, 공유 카드 |
| 개인 기록 관리 | 기기 저장, 내보내기·가져오기 |

## 구현과 확인할 코드

- [app.js](app.js): 상태 판정, 3일 사이클, 누적 기록, 복귀 흐름
- [index.html](index.html), [style.css](style.css): 모바일 중심 화면과 테마
- [native.js](native.js): Capacitor를 통한 알림·햅틱·공유 연결
- [pwa.js](pwa.js), [sw.js](sw.js): 웹 설치와 오프라인 동작
- [test](test): 주요 흐름, PWA, 화면 명암비 검사

웹 코드로 PWA와 모바일 앱을 구성했습니다. 네이티브 앱은 Capacitor로 패키징합니다. **이 프로젝트에는 LLM 기능이 없습니다.** AI 서비스 지원 포트폴리오에서는 문제 정의와 제품 설계, 실제 배포 경험을 보여주는 사례입니다.

## 제 기여와 AI 도구 활용

3일 단위 습관과 복귀 경험을 핵심으로 하는 제품 방향, 화면 문구, 기록 방식, 측정 지표를 정리하고 앱 구현·검증 과정에 참여했습니다. AI 코딩 도구를 활용해 코드를 작성·수정했으며, 생성된 코드까지 모두 수작업으로 작성했다고 주장하지 않습니다. 설계 이유는 [제품 문서](docs/POSITIONING.md), 구현·빌드 과정은 [BUILD.md](BUILD.md)에서 확인할 수 있습니다.

## 실행

간단히 확인하려면 `index.html`을 브라우저에서 열 수 있습니다. 개발용 로컬 서버를 쓰려면:

```bash
python3 -m http.server 8000
```

전체 테스트와 앱 빌드에는 Node.js 22 이상이 필요합니다.

```bash
npm ci
npm test
npm run build
```

iOS·Android 프로젝트를 여는 절차는 [BUILD.md](BUILD.md)를 참고하세요. 이 README의 실행 명령은 문서와 코드에서 확인한 내용이며, 이번 검토 환경에서 새로 테스트를 완료했다는 뜻은 아닙니다.

## 공개 상태

Google Play의 공개 페이지에서 셋돌하나 앱을 확인할 수 있습니다. 다운로드 수나 사용자 유지율 같은 성과는 확인 가능한 자료가 없어 기재하지 않았습니다.
