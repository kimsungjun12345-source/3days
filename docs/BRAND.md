# 셋돌하나의 그림 — 돌 · 워드마크 · 아이콘

이 문서는 취향을 적는 자리가 아니라 **시안이 코드에 들어맞게 하는 치수표**다.
그림이 예쁜지는 눈으로 정하고, 여기 적힌 값은 재서 정한다.

셋이 한 벌이어야 하는 이유는 이 앱의 규칙이 `3일 → 돌 하나 → 다시 쌓기`
하나뿐이기 때문이다. 돌이 브랜드의 가장 고유한 시각 언어이므로 **돌을 먼저
정하고, 그 둥근 정도를 보고 워드마크를, 마지막에 아이콘을** 만든다.

## 그림체

**Soft Pebble Garden** — 정원에서 하나씩 주워 모은 조약돌.

- 낮은 채도 · 둥글고 약간 비정형 · 손으로 만진 듯한 형태
- 그림자 최소 · 3D가 아니라 2.5D
- 하지 않는 것: 광택 3D · 과한 그라데이션 · **얼굴 달린 돌** · 반듯한 SaaS 로고

귀여움은 형태와 움직임이 만든다. 돌이 살짝 기울고, 툭 놓이고, 작게
흔들렸다 멈추는 것으로 충분하다. 얼굴을 붙이는 순간 이 앱은 캐릭터 습관
앱이 되고, 잡아 둔 방향(차분함 · 회복 · 작은 성취)에서 벗어난다.

## 돌 — 여기가 70%다

### 실루엣 세 종의 조건

`pebble-a.svg` · `pebble-b.svg` · `pebble-c.svg`.

**셋의 발자국(bounding box)이 같아야 한다.** 이것이 이 문서에서 가장
중요한 한 줄이다. 그리고 **발자국이 같다는 것은 모양이 같다는 뜻이 아니다** —
셋 다 상자의 네 변에 닿되, 그 사이를 잇는 곡선은 눈에 띄게 달라야 한다.

돌마다 실루엣을 달리하는 것은 이 저장소에서 **두 번 시도해 두 번 물린**
방향이다. 한 번은 3일마다 모양을 고르게 하던 `goal.stoneShapes`였고, 한 번은
조약돌 윤곽(점 열 개를 씨앗값으로 민 닫힌 곡선)이었다. 두 번째 주석이
남아 있다 — *"가까이 보면 손으로 주운 돌 같았지만, 여러 채가 서면 울퉁불퉁한
덩어리로 뭉쳐 보였다."*

원인은 아이디어가 아니라 진폭이었다. 폭과 높이가 층마다 달라지면 탑 윤곽이
지그재그가 되고, 그러면 정돈된 정원이 아니라 부스러기 더미로 읽힌다.
그러니 셋은 **가로·세로를 같게 두고 가장자리 성격만** 다르게 한다 — 한쪽이
눌린 정도, 곡률이 꺾이는 자리, 좌우 비대칭.

**다만 "2~3% 미세 변형"으로는 안 된다.** 실제로 그려서 겹쳐 봤더니 차이가
아예 보이지 않았다. 반지름을 3% 흔들면 150px 그림에서 1.2px이고, 정원
크기(40~60px)에서는 0.5px — 서브픽셀이라 없는 것과 같다. "따로 보면 다르고
탑으로 보면 같아 보이는" 목표를 이 진폭으로 잡으면 두 크기 모두에서 그냥
같아 보인다.

쓸 만한 진폭은 **10% 안팎**이었다. 한쪽 위를 10% 눌러 넣고 반대쪽 아래를
10% 밀어내면 낱개로는 확실히 다른 돌인데, 발자국이 고정되어 있어 탑은
그대로 단정하다.

**발자국은 손으로 지키지 않는다.** 곡률을 흔든 만큼 상자가 커지거나 작아지기
때문에, 그린 뒤에 실제 경계를 재서 다시 눌러 넣는 일(`fitBox`)을 코드가
한다. 그래야 Figma에서 자유롭게 그려도 탑에서 층 높이가 안 흔들린다.

### SVG 형식

```
viewBox="0 0 100 100"      셋 다 동일. 돌이 차지하는 영역도 셋 다 동일
<path class="pebble-top">  윗면 곡선 하나. 이것만 주면 된다
```

**옆면은 그리지 않는다.** 윗면 곡선에서 벽을 세우고 음영을 넣는 일은 코드가
한다(아래 '입체로 보이게 하는 것' 참고). 옆면까지 SVG에 넣으면 6색 × 2테마를
SVG로 감당해야 하고, 벽 높이 변주 같은 값도 손으로 맞춰야 한다.

- **fill을 넣지 않는다.** 작심마다 다른 색을 코드가 입힌다. 색이 박혀
  있으면 6색이 하나도 안 먹는다
- **옆면을 어둡게 하는 것도 코드가 한다.** 그래야 6색 × 2테마 = 12벌을
  SVG 12개로 만들지 않아도 된다
- **그림자를 SVG에 넣지 않는다.** 홈·정원·공유 카드·아이콘이 각각 다른
  거리에서 보므로 상황별로 코드가 건다
- 하이라이트는 없어도 되고, 있어도 한쪽에 아주 미세하게

### 입체·질감은 모양이 아니라 겹으로 칠해 만든다

여기까지 오는 데 세 번 물렸다. 그 실패들이 지금 방식을 정했으므로 남긴다.

1. **옆면을 벽으로 세워 봤다(퍽).** 곧은 원통 벽은 조약돌이 아니라 하키
   퍽이다. 두껍게 하면 치즈 덩어리, 얇게 하면 다시 퍽.
2. **윗면을 안쪽에 얹어 봤다(조개).** 밝은 안쪽 타원 + 어두운 테두리 두
   톤이 정확히 백합조개 속살로 읽혔다.
3. **단일 매트 그라데이션(플라스틱).** 조개는 없앴지만 표면 결이 없어
   매끄러운 플라스틱이 됐다.

결론 — 돌은 **하나의 조약돌 path**에 겹을 쌓아 칠한다. 벽도, 얹은 윗면도
없다.

| 겹 | 무엇 |
|---|---|
| 볼륨 | 방사 그라데이션. 중심을 위-왼쪽(40%,28%)에 두고 가장자리로 어둡게 (`--stone-top-1`→`4`) |
| 배(belly) | 아래쪽 초승달 그림자 — 바닥에 얹힌 느낌(접지) |
| 림(rim) | 윗머리 아주 옅은 반사광 |
| 얼룩(mottle) | 낮은 주파수 `feTurbulence`를 **multiply**로 아주 옅게 — 자연스러운 톤 변화 |
| 결(grain) | 높은 주파수 `feTurbulence`를 **soft-light**로 — 표면 거칠기. 이게 없으면 플라스틱이다 |

- **불투명하게 그린다.** 정원이 뒤 탑에 opacity를 낮춰 대기 원근을 주면,
  탑이 옆으로 겹칠 때 뒤 돌이 비쳐 유리처럼 읽힌다. 거리는 크기·자리·그리는
  순서(뒤부터)로만 준다.
- **그레인이 크기에 정직하다.** 정원의 탑 하나는 40~60px이라 결이 잘 안
  보인다. 세게 주면 지글대는 노이즈(AI 티)가 되므로, 대신 정원 돌을 키워
  (`ry`를 자연비율의 0.77로, 배율 0.70) 결이 보이게 했다. 결을 키우지 말고
  돌을 키운다.

**이 겹들은 Figma가 아니라 코드가 한다.** SVG는 윗면 곡선 하나만 주면 된다
— 볼륨·배·림·얼룩·결·색(6색×2테마)이 전부 그 곡선에서 코드로 나온다.

### 색 — 여섯 벌이 필요하다

작심 자리는 **6개**다(`GOAL_LANES`가 여섯 — 정원에 줄이 여섯이라 그 이상은
설 자리가 없다). 다섯만 정하면 여섯 번째 작심이 색을 재사용한다.

그리고 **밝은 화면용과 어두운 화면용을 따로** 정한다. 같은 값을 그대로 쓰면
어두운 배경에서 밝은 돌이 떠 보인다 — 예전에 그래서 갈라놓았다.

원본 팔레트(source palette) — 그대로 쓰지 않는다. 아래 '채도' 항 참고.

밝은 화면:

| Sage Stone | `#A9B4A0` |
| Dusty Blue Stone | `#A9B9C4` |
| Clay Stone | `#C89D8A` |
| Cool Gray Stone | `#B5B4B0` |

어두운 화면(밝게가 아니라 채도·명도를 함께 눌러 배경에 묻히게):

옆면은 각 색보다 10~15% 어둡게 — 코드가 계산한다.

### 채도 — 원본을 그대로 쓰지 않는다

**여섯을 실제로 세워 보니 색이 먼저 읽혔다.** 위 팔레트는 앞선 결정을
뒤집는 것이고, 지금 코드는 *"색을 세게 주면 정원이 아니라 색깔 범례가
된다"*고 적어 두고 채도를 거의 0으로 두었었다. 정원 탭에 여섯 채를 세운
그림에서는 초록·파랑·주홍·보라가 먼저 보이고 돌은 그다음이었다 — 정해 둔
기준("색보다 돌이 먼저 보여야 한다")에 걸린다.

그래서 **제품에 쓰는 값은 원본의 채도를 60%로 낮춘 것**이다. 45%는 예비다.

| | 밝은 화면 | 어두운 화면 |
|---|---|---|
| Warm Stone | `#C1B8AB` | `#A09486` |
| Sage Stone | `#A9B0A4` | `#899285` |
| Dusty Blue | `#AEB8BF` | `#89959C` |
| Clay Stone | `#BCA296` | `#9B8279` |
| Cool Gray | `#B4B3B1` | `#91908E` |
| Muted Mauve | `#B5AAB2` | `#92878F` |

**통과 조건은 눈으로 정한다** — 여섯 돌탑을 한 화면에 세웠을 때 '색'보다
'돌'이 먼저 보이면 통과다. 값을 바꾸면 그 화면을 다시 본다.

### 시안은 작게 놓고 판단한다

정원에서 탑 하나는 **40~60px**이다. 1024px에서 아름다운 조약돌이 거기서는
회색 알약이 된다. 아이콘을 48px 옆에 놓고 그리듯, 돌도 축소본을 옆에 놓고
그린다.

## 워드마크 — 30%

기존 폰트를 그대로 쓰기보다 둥근 한글을 조금 손본다. 획 끝이 둥글고, 너무
두껍지 않고, 글자 폭이 넉넉하고, `ㅅ`·`ㄷ`·`ㅎ`의 각진 데를 살짝 부드럽게.
완벽하게 균일하지 않은 2~3%의 손맛. 전체는 한 줄.

강조는 `하나`에만, 그것도 아주 미묘하게. `셋돌 하나!!`처럼 보이면 안 된다.

### 색

| | 값 | 비고 |
|---|---|---|
| 기본 | `#3F3B36` | 밝은 배경에서 10.28:1 — 넉넉하다 |
| 강조 | 쓰지 않는다 | 아래 참고 |

**첫 버전은 단색으로 간다.** `하나` 전체를 강조색으로 칠하면 워드마크에서
회복색이 차지하는 면적이 생각보다 크다. 전체를 `currentColor`로 두고,
sage는 앱 UI 안에서만 쓴다. 단색이 너무 밋밋할 때에만 아주 작은 디테일
하나(획 하나, 글자 옆 돌 점 하나)를 실험한다 — 억지로 넣을 필요는 없고,
첫 버전은 단색이 더 오래 갈 가능성이 높다.

참고로 제안됐던 `#7F967A`는 밝은 배경 `#f7f6f3` 위에서 **2.97:1**이라
큰 글자 기준(3:1)도 못 넘긴다. 못 쓴다.

**이 값을 미리 맞춰야 하는 이유가 따로 있다.** 워드마크가 글자일 때는
`test/contrast.js`가 밝은/어두운 4조합을 자동으로 재 준다. SVG 이미지가 되는
순간 그 그물에서 빠진다 — 자동으로 잡히지 않으니 사람이 재서 넣어야 한다.

### Sage = 다시 시작함 / 회복

브랜드 색과 회복 색을 **한 벌로 합친다.** 이 앱의 정체성이 '다시 돌아오는
것'이므로, 브랜드 accent와 복귀 accent가 같은 색인 편이 오히려 강하다.
색에 제품의 뜻이 생긴다.

| | 값 | 대비 |
|---|---|---|
| 밝은 화면 | `#617459` | 4.68:1 |
| 어두운 화면 | `#86A578` | 6.66:1 |

한때 `#63775A`로 정할 뻔했는데 그 값은 AA 본문 기준(4.5)을 **0.0012 차이로**
넘는다. 기술적으로는 통과지만 배경을 한 톤만 건드려도 `npm test`가 깨지는
여유다. `#617459`는 눈으로 구분이 안 되면서 숨 쉴 자리가 있다.

**아무 데나 쓰지 않는다.** 일반적인 성공·설정·장식에 sage를 뿌리면 희소성이
사라지고, 그러면 색으로 뜻을 나른다는 계획 자체가 무너진다. 복귀와 브랜드
정체성에 연결된 자리에만 쓴다.

### SVG 형식

```
wordmark.svg          한 개
viewBox만 유지          width/height 하드코딩 제거
배경 없음
<g class="wordmark-main">     fill="currentColor" — 테마마다 CSS가 색을 준다
<g class="wordmark-accent">   강조만 별도 그룹
```

글자는 **Flatten으로 path 변환**한다(`Outline Stroke`는 stroke를 path로
바꾸는 기능이라 텍스트 벡터화에는 맞지 않는다). `<text>`가 남아 있으면
폰트 없는 기기에서 엉뚱하게 렌더된다.

이미지가 되어도 **읽어 주는 이름은 남긴다** — 앱바의 `<h1>`은 스크린리더가
읽을 글자를 그대로 갖고 있어야 한다.

## 아이콘

앱 안의 돌탑을 그대로 축소하지 않는다. 48px에서 한눈에 보여야 한다.

두 안을 시안으로 만들어 비교한다.

- **A — 조약돌 셋.** 이름의 `셋 + 돌`을 직관적으로 표현한다. 높은 탑보다
  삼각 구성이 아이콘에서 안정적일 수 있다. 첫인상이 예쁠 가능성이 높다
- **B — 돌 하나 + 세 개의 흔적.** 큰 돌 하나 안에 아주 작은 패임이 셋.
  `3일 → 돌 하나`라는 메커니즘을 가장 정확히 표현하고 심볼로 더 독창적이다.
  다만 처음 보는 사람에게는 더 추상적이다

아이콘은 브랜드 상징이지 인앱 메커니즘의 설명이 아니므로, 앱 아이콘이 돌
셋이고 앱 안의 보상이 돌 하나여도 어긋나지 않는다. A는 돌 셋이 '3일'로
오해될 여지가 있다는 점만 염두에 둔다.

**48px에서 갈린다.** 두 안을 그려 줄여 보니 A는 32px에서도 '돌 셋'이
남는데, B의 흔적 셋은 작게 그리면 뭉개져 아예 안 보였다. 흔적을 키우고
진하게 하면 48px까지는 살아남지만, 그만큼 '작은 패임'이라는 느낌은 옅어지고
점 셋을 박은 돌에 가까워진다. B로 간다면 이 맞바꿈을 인정하고 흔적을
크게 그려야 한다.

1024×1024 마스터 하나만 만든다. 나머지 크기는 `scripts/make-native-assets.js`가
만든다.

### 놓치기 쉬운 두 가지

- **안드로이드 어댑티브 아이콘은 바깥 33%가 잘린다.** 심볼을 가운데
  **66% 원 안**에 둔다. 지금 스크립트는 inset 10%인데, 그 값까지 꽉 채우면
  둥근 마스크에서 돌 끝이 날아간다
- **iOS 앱스토어 아이콘은 투명과 둥근 모서리가 금지**다. 배경을 꽉 채운
  정사각형으로 만든다 — 모서리는 애플이 씌운다

## 바뀌면 함께 바뀌는 것

돌 모양은 **세 군데에 따로 구현되어 있다.** 하나만 고치면 나머지 둘이
조용히 어긋난다.

| | 무엇 |
|---|---|
| `app.js` `stonePiece()` | 앱 화면의 돌 (SVG, 층마다 계산해서 그린다) |
| `scripts/make-native-assets.js` | 앱 아이콘 · 스플래시 |
| `share.js` `drawTower()` | 공유 카드 (SVG가 아니라 Canvas다) |

그리고 다시 뽑아야 하는 것들 — 전부 스크립트가 만든다.

```bash
node scripts/make-native-assets.js   # 아이콘 · 스플래시 (안드로이드/iOS 전 크기)
node scripts/make-store-shots.js     # 스토어 스크린샷 15장
node scripts/make-feature-graphic.js # 피처 그래픽 1024×500
npm test                             # 명암비 포함
```
