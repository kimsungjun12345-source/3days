# 스토어 등록 문구

그대로 복사해 쓸 수 있게 정리했습니다. 핵심은 하나입니다 —
**이 앱은 습관을 지키게 하는 앱이 아니라, 못 지킨 다음에 돌아오게 하는 앱입니다.**
모든 문구가 그 한 가지를 말합니다.

## 왜 이 순서로 쓰는가

솔로 개발자가 만든 습관 앱 HabitKit은 2025년에 60만 달러를 벌었는데,
**사용자의 98%가 스토어 검색에서 왔습니다.** 광고도, 트위터도, 틱톡도 아니었고요.
그러니 이 문서가 사실상 이 앱의 유일한 마케팅 자산입니다. 공들일 값어치가 있습니다.

두 스토어는 색인하는 곳이 다릅니다.

| | 검색에 색인되는 것 | 특징 |
|---|---|---|
| **Google Play** | 앱 이름 · 짧은 설명 · **전체 설명 전부** | 한국 다운로드 볼륨의 대부분. 설치 수·이탈률 같은 품질 지표도 순위에 반영 |
| **App Store** | 앱 이름 · 부제 · **키워드 필드(100자, 비공개)** | 설명은 색인 안 됨. 다운로드 속도에 민감 |

Play는 설명 본문에 검색어가 자연스럽게 들어가야 하고, App Store는 설명에
검색어를 넣어 봐야 소용없고 **키워드 필드 100자**가 전부입니다.
결과는 보통 2~4주 뒤 키워드 순위부터 움직입니다.

```
작심삼일 - 3일 습관 만들기, 루틴 기록
```

**App Store** (30자 이내)

```
작심삼일 : 습관 만들기
```

부제 (App Store, 30자 이내 — 이름과 함께 색인됩니다)

```
3일씩 쌓는 습관 · 무너져도 괜찮아요
```

짧은 설명 (Play, 80자 이내 — 색인됩니다. 검색어와 후크를 같이 담습니다)

```
연속 기록이 끊겨도 괜찮은 습관 앱. 약속은 딱 3일, 채우면 돌 하나. 무너져도 쌓은 건 남아요.
```

프로모션 텍스트 (App Store, 170자 — 색인 안 됨. 심사 없이 언제든 교체 가능)

```
습관 앱을 깔았다가 지워본 적 있나요? 하루 빠뜨린 순간 연속 기록이 0이 되고,
그날로 앱을 열지 않게 되죠. 작심삼일은 3일마다 새로 시작합니다.
무너져도 쌓아 둔 돌은 그대로예요.
```

## 전체 설명

Play에서는 이 본문 전체가 검색에 색인됩니다. 첫 세 줄이 '더보기' 전에 보이므로
가장 강한 문장을 앞에 둡니다.

```
연속 기록이 끊겨서 습관 앱을 지워본 적 있나요?

「작심삼일」은 3일 만에 포기하는 앱이 아니라, 3일씩 해내는 앱입니다.
약속은 딱 3일. 3일을 채우면 돌 하나가 쌓이고, 무너지면 다시 쌓으면 됩니다.
돌탑은 원래 무너지면 다시 쌓는 것이니까요.


▶ 연속 기록이 0이 되지 않습니다

대부분의 습관 앱은 하루를 빠뜨리면 며칠을 쌓았든 0으로 돌려보냅니다.
그 숫자가 길어질수록 잃는 것이 무서워지고, 결국 앱과 습관을 함께 놓게 되죠.

작심삼일에는 그 숫자가 없습니다.
3일이 한 묶음이라 언제든 새로 시작할 수 있고,
쌓아 둔 돌은 무슨 일이 있어도 그대로 남습니다.


▶ 약속은 딱 3일

거창한 목표 대신 사흘만 약속합니다.
"아침에 물 한 잔", "10분 걷기", "자기 전 스트레칭" 같은 작은 것으로 충분해요.
3일이면 누구나 해볼 만하니까요.

하루에 칸 하나씩, 세 칸을 채우면 돌 하나입니다.


▶ 돌이 모여 나의 돌탑 정원으로

돌 다섯 개(15일)를 채우면 탑 한 채가 완성되고,
그다음 돌부터는 그 옆에 새 탑이 섭니다.
오래 다닌 사람의 자리에는 탑이 여러 채 서 있게 됩니다.

작심마다 돌의 결과 빛깔이 달라서, 어느 탑이 무엇이었는지 한눈에 보입니다.
작심삼일 120번이면 360일입니다. 진짜로요.


▶ 무너져도 사라지지 않아요

하루를 건너뛰어도 쌓아 둔 돌은 그대로 남습니다.
"실패"라고 부르지 않고, 며칠 쉬었는지만 조용히 알려드려요.
그리고 돌아오면 이렇게 인사합니다.

"돌아왔네요. 그거면 충분해요."

그러니 놓친 날을 되돌리는 기능도 없습니다. 필요하지 않으니까요 —
잃은 것이 없는데 되돌릴 것도 없습니다.


▶ 다시 쌓은 횟수가 진짜 기록

이 앱은 '며칠 연속'을 자랑하지 않습니다.
대신 '몇 번 다시 왔는가'를 셉니다.
무너지고도 돌아온 사람이 결국 탑을 완성하니까요.

달력에는 빈칸도 함께 보입니다. 그 빈칸도 이야기의 일부라
지우거나 되돌릴 수 있게 하지 않았습니다.
작심마다 색이 달라서, 어느 날 무엇을 했는지 한눈에 보입니다.


▶ 조용한 알림

정해진 시각에 한 번, 오늘 남은 칸이 있을 때만 알려드립니다.
시간은 분 단위로 원하는 대로 정할 수 있고,
알림에서 바로 "오늘 했어요"를 눌러 앱을 열지 않고 체크할 수 있습니다.

쉬고 있을 때는 재촉하는 대신 이렇게 말합니다.
"쌓아 둔 돌 5개는 그대로예요."


▶ 기록은 내 기기에만

계정도, 로그인도, 광고도 없습니다.
모든 기록은 기기 안에만 저장되고 어디로도 전송되지 않습니다.
필요하면 파일로 내보내 두었다가 언제든 되살릴 수 있어요.
인터넷 없이도 그대로 동작합니다.


이런 분께 맞습니다
· 습관 앱을 깔았다가 며칠 만에 지워본 분
· 연속 기록이 끊기면 그대로 놓아 버리는 분
· 갓생이나 미라클모닝이 부담으로 느껴지기 시작한 분
· 화려한 대시보드 말고 조용한 화면을 원하는 분


작심삼일도 여러 번 하면, 평생이 됩니다.
```

## 키워드 (App Store, 100자 이내)

쉼표로만 구분하고 **띄어쓰기를 넣지 않습니다**(띄어쓰기도 글자 수를 먹습니다).
앱 이름·부제에 이미 있는 말은 넣지 않아도 조합으로 검색됩니다.

```
루틴,루틴관리,갓생,자기계발,체크리스트,목표관리,챌린지,미라클모닝,플래너,동기부여,다짐,기록,오운완,habit
```

**전략**: '습관 트래커'는 레드오션입니다. 처음에는 경쟁이 없는 곳에서 1등을 하는 편이
낫습니다 — **작심삼일**은 검색량이 있는데 경쟁자가 없는 브랜드 키워드이고,
앱 이름 자체가 ASO 자산입니다. 여기서 평점과 설치 속도를 쌓은 뒤
'습관 만들기' → '습관'으로 올라가는 순서로 갑니다.

## 스크린샷

**첫 두 장이 전부입니다.** 대부분의 사용자는 스크롤하지 않고, 검색 결과에서도
앞의 두세 장만 미리 보입니다. HabitKit이 성공한 이유도 '한눈에 알아보는 그림'
하나였습니다 — 우리에게는 돌탑 정원이 그것입니다.

| # | 무엇을 보여주나 | 큰 카피 | 보조 문구 |
|---|---|---|---|
| 1 | **돌탑 정원** (탑 여러 채) | 3일마다, 돌 하나 | 쌓인 것이 눈에 보입니다 |
| 2 | **무너진 카드 + 그대로인 탑** | 하루 빠뜨려도 돌은 그대로 | 연속 기록이 0이 되지 않아요 |
| 3 | 작심 카드의 세 칸 | 하루에 한 칸, 3일이면 돌 하나 | 거창하지 않아도 괜찮아요 |
| 4 | 탑 완성 축하 화면 | 15일마다 탑 한 채 | 다음 돌부터는 새 탑이 섭니다 |
| 5 | 기록 탭 달력 | 다시 쌓은 횟수가 진짜 기록 | 빈칸도 이야기의 일부입니다 |
| 6 | 어두운 화면의 정원 | 밤에도 조용하게 | 저녁에 여는 앱이니까요 |

1번과 2번의 순서가 이 앱의 주장을 그대로 담습니다 — *쌓인다*, 그리고 *잃지 않는다*.

크기별로 `ios-6.7`(1290×2796), `ios-6.5`(1242×2688), `android`(1080×1920)가
준비되어 있습니다. 다시 만들려면:

```bash
node scripts/make-store-shots.js
```

## 출시 직후 할 것 (첫 1000명)

ASO는 결과가 2~4주 뒤부터 나옵니다. 그동안 손 놓고 기다리지 않으려면:

1. **평점 먼저.** 스토어 순위는 평점을 크게 반영합니다. 탑 한 채(15일)를
   완성한 사용자에게만 평가를 청합니다 — 가장 기분 좋은 순간이고, 그때 남는
   평점이 진짜입니다. 설치 직후에 묻는 것은 최악입니다.
2. **공감이 도는 곳에 이야기로.** 자랑이 아니라 "연속 기록 깨져서 앱 지워본 사람"
   이야기로 접근합니다. 갓생 번아웃 이야기가 도는 커뮤니티가 맞는 자리입니다.
3. **만드는 과정을 공개.** HabitKit도 초기 사용자와 첫 평점은 build in public에서
   나왔습니다. 돌탑이 자라는 화면은 그 자체로 볼거리입니다.
4. **공유 카드를 지켜볼 것.** 탑을 세운 사람에게만 권하고, 카드에는 자랑하는
   숫자가 아니라 "N번 멈췄다가 다시 왔어요"를 싣습니다. 부러움보다 공감이
   멀리 갑니다.

## 심사 메모 (App Review Notes)

```
로그인이나 계정이 필요 없는 앱입니다. 모든 기록은 기기 내부(localStorage)에만
저장되며 서버로 전송하지 않습니다.

알림은 서버 푸시가 아니라 기기 안에서 예약하는 로컬 알림입니다.
첫 체크인을 마친 뒤 앱 안에서 이유를 설명하는 화면을 먼저 보여드리고,
사용자가 동의했을 때에만 시스템 권한을 요청합니다. 설정에서 끄면 예약된
알림이 모두 취소됩니다.

확인 방법: 앱을 처음 열면 '무엇을 3일 해볼까요?'라는 화면이 바로 뜹니다.
추천 문구 중 하나를 고르고 '3일 약속하기'를 누른 뒤, 카드의 '오늘 해냈어요'를
누르면 핵심 기능을 바로 확인하실 수 있습니다.
```

## 등록에 필요한 주소들

수집하는 정보가 없어도 두 스토어 모두 방침 **URL**을 요구합니다. 파일을
올리는 것이 아니라 열리는 주소여야 하고, 애플은 링크가 깨진 것을 거절
사유로 따로 적어 두고 있습니다.

`scripts/build.js`가 `store/privacy.html`을 `www/privacy.html`로 함께
옮기므로, 웹 배포(`.github/workflows/pages.yml`)를 한 번 돌리면 아래
주소가 그대로 열립니다.

| 항목 | 주소 | 어디에 |
|---|---|---|
| 개인정보 처리방침 | `https://<계정>.github.io/3days/privacy.html` | Play·App Store 둘 다 (필수) |
| 지원(Support) URL | `https://<계정>.github.io/3days/` | App Store (필수) |
| 문의 이메일 | `trevicode@gmail.com` | Play 개발자 연락처 · 방침 본문 |

**등록 전에 두 주소를 실제로 열어 보세요.** 스토어 양식에 적어 넣기
전에 브라우저에서 확인하는 데 10초면 되고, 심사에서 되돌아오면 며칠입니다.

웹 배포는 손으로 돌립니다 — Actions 탭 → '웹 배포' → Run workflow.
저장소 Settings → Pages → Source 를 `GitHub Actions`로 먼저 바꿔 두어야
하고, 비공개 저장소라면 GitHub Pro가 필요합니다(또는 저장소를 공개로).
