# 테스트

실제 브라우저로 앱을 띄워 확인하는 검사들입니다.

```bash
npm ci
npx playwright-core install chromium   # 크로미움이 없는 환경에서 한 번만
npm test                               # 스모크 · PWA · 명암비 셋 다
```

검사 개수는 여기 적지 않습니다. 숫자를 박아 두면 검사를 하나 더할 때마다
문서가 틀리고, 틀린 줄은 아무도 고치지 않아 결국 전부를 못 믿게 됩니다.
지금 몇 개인지는 `npm test`가 말해 줍니다.

## 크로미움을 어디서 찾는가

경로는 `test/browser.js` 한 곳에서 정합니다. 세 파일에 각각 박아 두면
환경이 바뀔 때 한 곳만 고쳐지고 나머지가 조용히 죽기 때문입니다.

찾는 순서는 이렇습니다.

1. `CHROMIUM_PATH` — 직접 알려 준 경로
2. 브라우저 보관함(`PLAYWRIGHT_BROWSERS_PATH` 또는 `~/.cache/ms-playwright`)
   안에 이미 있는 크로미움. 빌드 번호는 묻지 않습니다
3. 못 찾으면 playwright가 제 것을 찾습니다

이미 크로미움이 있는데 위 순서로 못 찾는다면:

```bash
CHROMIUM_PATH=/실행/파일/경로 npm test
```

## 무엇을 보는가

- `smoke.js` — 작심 추가/삭제/고치기, 하루 1회 체크와 되돌리기, 3일 완주와
  3일 완주와 축하 화면, 완주 후 상태 흐름(당일 / 다음 날 / 방치), 다시 쌓기,
  작심 개수 상한, 돌탑 정원, 기록 화면, 내보내기·가져오기, 공유 카드
- `pwa.js` — 매니페스트와 아이콘, 서비스 워커 등록, 앱 셸 캐싱,
  네트워크가 끊긴 상태에서의 실행·기록·재실행, iOS 설치 안내
- `contrast.js` — 화면마다 보이는 모든 글자의 명암비(WCAG AA). 기기 설정과
  앱 설정이 엇갈린 조합까지 네 가지를 돕니다

화면을 새로 만들면 `contrast.js`의 `screens`에 등록해야 합니다. 눈으로
보는 것으로는 대신할 수 없습니다 — 흰 카드 위의 흰 글자는 실제로 한 번
빠져나간 적이 있습니다.
